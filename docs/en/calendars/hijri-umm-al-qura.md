# Hijri — Saudi Umm al-Qura (KACST)

The official Saudi calendar, with month lengths hand-curated per year by KACST based on astronomical observation and new-moon visibility predictions. This is what Persian websites display alongside Jalali, and what Saudi/Gulf users expect when an app shows them an Islamic date.

## Quick facts

| | |
|---|---|
| Class | `Eram\Daynum\Calendar\Hijri\HijriUmmAlQuraCalendar` |
| View | `Eram\Daynum\Calendar\Hijri\HijriUmmAlQuraView` |
| Identifier | `hijri-umalqura` |
| Locale family | `hijri` (shared with civil variant) |
| Year range | `AH 1300` to `AH 1600` (~1882 to ~2174 CE) |
| Source | Bundled from ICU's `islamic-umalqura` (originally KACST) |
| Default format | `Y/m/d` |

## Construction

```php
use Eram\Daynum\Instant;

Instant::fromHijri(1447, 10, 21);                        // Saudi UAQ
Instant::fromHijri(1447, 10, 21, 14, 30, 0, 'Asia/Riyadh');

Instant::tryFromHijri(1200, 1, 1);     // null — outside table range
Instant::isValidHijri(1447, 1, 31);    // false — Muharram has at most 30 days
```

## Bundled table

Daynum bundles ICU's `islamic-umalqura` table verbatim (`src/Calendar/Hijri/Table.php`, regenerated by `tools/generate-uaq-table.php`) so no `ext-intl` is needed at runtime.

The bundled table covers a fixed range — currently **AH 1300 to AH 1600** (roughly 1882 to 2174 CE), the exact window over which ICU exposes native KACST data. Always read `Table::MIN_YEAR` and `Table::MAX_YEAR` rather than assuming a particular pair of numbers — the window is pinned to the ICU version the table was generated from.

```php
use Eram\Daynum\Calendar\Hijri\Table;

Table::MIN_YEAR;      // 1300
Table::MAX_YEAR;      // 1600
Table::ICU_VERSION;   // e.g. "78.2"
```

## Why throw instead of silently falling back

Outside AH 1300–1600, ICU silently falls back to the arithmetic civil calendar. That kind of quiet divergence is precisely the kind of credibility hazard Daynum exists to prevent — a user displaying AH 1250 wouldn't know they were looking at `islamic-civil` output mislabeled as UAQ.

So Daynum **throws**:

```php
Instant::fromHijri(1200, 1, 1);
// → UmmAlQuraOutOfRangeException:
// "Hijri Umm al-Qura date 1200-01-01 is outside the supported range
//  (AH 1300 to AH 1600). Use fromHijriCivil() for dates outside this range."
```

### Recovery: fall back to civil

```php
use Eram\Daynum\Instant;
use Eram\Daynum\Exception\UmmAlQuraOutOfRangeException;

try {
    $d = Instant::fromHijri($year, $month, $day);
    $formatted = $d->hijri()->format('j F Y');
} catch (UmmAlQuraOutOfRangeException) {
    $d = Instant::fromHijriCivil($year, $month, $day);
    $formatted = $d->hijriCivil()->format('j F Y') . ' (civil)';
}
```

Or preflight with `isValidHijri()`:

```php
if (Instant::isValidHijri($year, $month, $day)) {
    $view = Instant::fromHijri($year, $month, $day)->hijri();
} else {
    $view = Instant::fromHijriCivil($year, $month, $day)->hijriCivil();
}
```

## UAQ boundary crossing via arithmetic

Arithmetic on a UAQ view returns an `Instant` — calendar-neutral — so the arithmetic itself never throws at the boundary. Viewing the *result* can throw, though:

```php
$d = Instant::fromHijri(1600, 12, 29);     // near table edge
$result = $d->hijri()->addDays(100);        // returns Instant (no error)
$result->hijriCivil()->year();              // works — civil has no range limit
$result->hijri()->year();                   // throws UmmAlQuraOutOfRangeException
```

See [../arithmetic.md](../arithmetic.md).

## Leap year rule

Unlike the civil variant, UAQ does not fix the leap day to Dhu al-Hijjah. Any month can have 29 or 30 days in any given year, and the leap test is "did this year have 355 days?" rather than "is Dhu al-Hijjah 30 days?".

```php
$view = Instant::fromHijri(1447, 1, 1)->hijri();
$view->isLeapYear();    // depends on year's bit-packed month lengths
```

## Formatting

```php
$d = Instant::fromHijri(1447, 10, 21);

$d->hijri()->format('j F Y');                                          // "21 Shawwal 1447"
$d->hijri()->withLocale('fa')->format('j F Y');                        // "21 شوال 1447"
$d->hijri()->withLocale('ar')->format('j F Y');                        // "21 شوال 1447"
$d->hijri()->withLocale('ar')->withDigits('arab')->format('j F Y');    // "٢١ شوال ١٤٤٧"
```

## Parsing

```php
use Eram\Daynum\Calendar\Hijri\HijriUmmAlQuraView;

HijriUmmAlQuraView::parseExact('1447/10/21', 'Y/m/d');
HijriUmmAlQuraView::tryParseExact('1200/1/1', 'Y/n/j');   // null — out of range
```

## Regenerating the bundled table

When ICU ships a new version of its Umm al-Qura data, regenerate with:

```bash
php tools/generate-uaq-table.php
```

See [../../../CONTRIBUTING.md](../../../CONTRIBUTING.md) for the full fixture-refresh procedure.
